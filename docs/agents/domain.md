# Domain docs

This repo uses a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Before exploring an area, read `GLOSSARY.md` and the relevant ADRs in `docs/adr/` if they exist. Missing files are not an error; create them only when domain terms or decisions have been resolved.

Use the glossary's terms in issues, proposals, hypotheses and tests. If an output conflicts with an ADR, identify the ADR and surface the conflict rather than silently overriding it.
